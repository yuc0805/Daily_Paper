Safin-1: Safety from Within through Memory-Native State Evolution

Zhang, Yang, Yu, Hua, Chen, Jin, Zheng, Sun, Lu (Shanghai AI Laboratory) · arXiv 2026 · link · arxiv_id: 2609.00092 · Appears in: Test-Time Training, MAMBA

What

Safin-1 is a family of foundation models built on MARCH, Memory-Anchor Routing across Context History, a network architecture that maintains structured memory states and retrieves relevant history through content-conditioned routing rather than attending over the full context. The same routed-state interface carries persistent capability states that can be adapted at test time without repeatedly modifying the backbone, which allows controlled specialization on top of a shared foundation. The paper investigates one such state, a Safety State, and reports substantial safety improvements from state-based adaptation, alongside evaluations of general capability, long-context understanding, retrieval, and efficiency. The authors present the work as an initial architectural exploration of the principle they call Safety from Within, and state that further work is needed.

Why

Long-horizon tasks require a model to accumulate information, hold internal state, and adapt across extended interactions, and safety behaviour has to survive all of that. The standard arrangements do not. External safeguards sit outside the model and judge its outputs without access to the state that produced them, and post-hoc alignment such as supervised fine-tuning writes a behavioural disposition into weights at one moment and cannot be revised without retraining. Both treat safety as a constraint applied to the model rather than a capability the model has, which is the specific gap the paper identifies. Prior memory work is insufficient for a different reason: it treats stored context as a passive record to retrieve from, so there is no place in the architecture to put a capability that should persist and evolve.

How

MARCH keeps structured memory states and selects among historical information by content-conditioned routing, which is what makes retrieval scale without attending over the whole history. Because the routing interface reads states rather than raw context, the same mechanism can address a persistent capability state, and adapting that state is a test-time operation that leaves the backbone untouched. The Safety State is the instance studied: safety-relevant capability is represented as a routed state and invoked through the model's own computation instead of by an external check. The broader claim the paper draws from this is that contextual memory and persistent capability adaptation are the same interface, so memory becomes an active substrate for maintaining and evolving behaviour rather than a record of prior context.

Solves vs predecessors

TTT Layers adapt an inner state to the current input and then discard it, so nothing learned during one interaction is available in the next, and a per-subject or per-deployment specialization has to be re-derived every time. That is the failure mode MARCH addresses by persisting the adapted state, which moves the unit of adaptation from a sequence to a deployment. Against the memory survey's framing, the gap closed is that a retrieval-only memory has nowhere to store a disposition, only facts, so safety behaviour had to live outside the architecture. Against Mamba, the fixed recurrent state compresses history but is not addressable as a separate installable capability, so specialization still means changing weights.

Method vs predecessors

Mamba mixes history into a single recurrent state updated by a selective scan; MARCH instead maintains multiple structured states and routes among them conditioned on content, which is closer to sparse retrieval than to recurrence and keeps the states separately addressable. Where TTT Layers make adaptation an inner-loop gradient step on a hidden state scoped to the input, Safin-1 makes it an update to a named persistent state that outlives the input and can be swapped or removed. The safety framing is downstream of this architectural choice rather than motivating it: once a capability can be a routed state, a safety capability is one of them, and it is invoked by the model's native computation instead of by a wrapper that sees only the output.
