TimeRecipe: A Time-Series Forecasting Recipe via Benchmarking Module Level Effectiveness

arXiv 2025-06-06 · arXiv:2506.06482 · Appears in: Signal/Time Series

What

TimeRecipe is a benchmarking framework that decomposes time-series forecasting architectures into individual modules (tokenization, normalization, attention, feed-forward layers, output heads) and measures which components drive accuracy, using over 10,000 experiments.

Why

The TS forecasting literature proposes many monolithic architectures, each bundling multiple design choices. It is unclear whether gains come from the overall architecture or from specific module choices. Without disentangling contributions, practitioners cannot rationally select components for new applications.

How

TimeRecipe implements a modular framework where each architectural component can be swapped independently. It systematically varies one module at a time across multiple backbone families (Transformer, MLP, CNN variants) and evaluates on standard forecasting benchmarks. The output is a ranked recipe of best module combinations per task type.

Builds on

  • PatchTST (Nie 2023)Introduced patch tokenization for TS Transformers; TimeRecipe evaluates whether this is the winning tokenization choice.
  • iTransformer (Liu 2024)Inverted the attention dimension to variate tokens; TimeRecipe isolates whether this choice alone drives gains.
  • TimesNet (Wu 2023)Proposed 2D periodicity decomposition; TimeRecipe tests whether this module transfers outside TimesNet's full pipeline.

Solves vs predecessors

Each predecessor proposed a complete architecture where all components are jointly optimized. It was impossible to know whether PatchTST's gains came from patching, channel independence, or the Transformer backbone. TimeRecipe disentangles these, showing that module-level choices (especially tokenization and normalization) often matter more than the overall architecture family.

Method vs predecessors

PatchTST, iTransformer, and TimesNet each evaluated their full architecture on benchmarks. TimeRecipe instead holds all other modules constant and varies one at a time, running a factorial experiment design across >10K combinations. This is a meta-analysis of architectures rather than a new architecture proposal.
