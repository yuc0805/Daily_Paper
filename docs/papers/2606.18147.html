WEQA: Wearable hEalth Question Answering with Query-Adaptive Agentic Reasoning

Zhang, Xia, Emmerich, Wu, Spathis, Liu, McDuff, Mascolo · arXiv 2606.18147 2026 · link · Appears in: Signal/Time Series

What

WEQA answers plain-language questions about wearable health data. A language-model controller writes an execution plan for each question and routes it to a matching set of tools (signal-analysis routines and pretrained wearable models), then composes the tool outputs into a natural-language answer. The routing is query-adaptive, so a sleep question and a cardiac question call different tools. The framework reports 24% higher accuracy than baseline approaches with clinician-judged clinical soundness.

Why

Wearable streams are continuous, high-dimensional, and longitudinal, so they do not align with the text-heavy data language models were trained on. Feeding raw signals or simple summary statistics into a language model loses the structure that matters for a clinical answer, and a single fixed pipeline applies the same tools to every question regardless of type. Prior work either described sensor windows or built one general agent, but did not match each question to the right analytical tool.

How

A language-model controller synthesises a per-query execution plan and routes the question to a combination of signal-analysis routines and pretrained wearable models. The selected tools run, and the controller composes their outputs into a natural-language answer. Because routing depends on the query, different question types invoke different tools rather than a shared pipeline.

Solves vs predecessors

Sensor2Text stops at a description of a sensor window; WEQA goes further to answer a specific clinical question, because a description is not yet an answer. TS-Agent applied a fixed set of analysis tools; WEQA adds query-adaptive routing so the tool set changes with the question, which fixes the failure where one pipeline is wrong for some question types. The reported 24% relative accuracy gain comes from this routing step.

Method vs predecessors

Where TS-Agent and LATS use a controller to plan over web, code, or generic analysis actions, WEQA points the controller at sensor-analysis routines and pretrained wearable models. It extends the cross-area bridge Sensor2Text to Health-LLM (bio-sensing to LLM-health) by adding agentic tool routing, so the bridge now reaches the agent community rather than ending at single-pass captioning.
