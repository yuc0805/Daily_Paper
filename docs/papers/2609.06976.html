HealthLoopQA: A Context-Aware Question Answering Benchmark for Interpreting Wearable Monitoring Data in Diabetes Care

Anonymous (under review) · arXiv preprint 2026 · arXiv:2609.06976 · Appears in: LLM-Health

What

A diagnostic benchmark for language model reasoning over continuous diabetes monitoring data, built on a simulated hybrid closed-loop insulin delivery testbed rather than a collected dataset. The testbed produces physiological and therapeutic traces under varied patient activity schedules and injects 17 fault scenarios covering device failures and security compromises. Question templates cover process mining, anomaly detection and predictive reasoning, graded by reasoning depth from descriptive statistics through causal and inferential reasoning, and each item carries both a numerical answer and a textual rationale so that quantitative accuracy and reasoning fidelity are scored separately.

Why

Existing wearable question-answering benchmarks assess short-horizon classification or statistical summaries. They therefore omit three things that determine whether a system is usable in chronic care: long-term patterns that only appear over months, the therapeutic and behavioral context that explains why a signal moved, and the system faults that occur in real deployments. The last is the sharpest gap, because a device failure and a physiological event can produce the same trace, and no observational dataset contains enough labeled failures to test whether a model can separate them.

How

Simulation supplies what observation cannot: the generating process is known, so every question has a ground-truth causal answer, and faults can be injected on demand rather than waited for. Activity schedules are varied to produce realistic behavioral context, and the 17 fault scenarios span both hardware failure and adversarial compromise. The reasoning-depth grading is what makes it diagnostic, since a system can be strong on descriptive statistics and fail on causal attribution, and a single score would hide that. Requiring a rationale alongside each numerical answer separates a model that reaches the right number by the right route from one that does not.

Builds on

  • Verifiable Physiological Reasoning (Wang 2026)Established that a physiological answer should be checked against an explicit derivation; this benchmark carries that requirement into every item via the paired rationale.
  • Health-LLM (Kim 2024)The short-horizon wearable evaluation setup this paper argues is too narrow for chronic-care deployment.
  • TS-Agent (Liu 2025)The tool-using, evidence-logging pattern that the process-mining and anomaly-detection question types are designed to reward.

Solves vs predecessors

Health-LLM's failure mode is that it cannot ask a causal question, because an observational wearable dataset does not record why a signal moved. HealthLoopQA fixes this by generating the data from a known process, which makes causal and inferential items answerable and gradeable. The second failure mode it fixes belongs to the whole prior line: no benchmark scored whether a model can distinguish a sensor fault from a physiological event, so a system that treats every anomaly as clinical was indistinguishable from one that does not. Fault injection makes that distinction measurable.

Method vs predecessors

Where Wang 2026 verified a single derivation, this paper attaches a rationale to every item and scores reasoning fidelity as a separate quantity from numerical accuracy, which turns verification from a method into an evaluation axis. Where TS-Agent showed that operator calls beat direct reading on time-series reasoning, this supplies the setting where the gap should be largest, since fault attribution requires evidence gathering rather than pattern recall. The design trade is explicit and is the opposite of WearableQA's: simulation buys controlled faults and ground-truth causal structure at the cost of authentic sensor distributions.
