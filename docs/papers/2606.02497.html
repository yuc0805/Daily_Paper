Bridging the Last Mile of Time Series Forecasting with LLM Agents

Liao, Wang, Nie, Zhang · arXiv 2026 · arXiv:2606.02497 · Appears in: Signal/Time Series

What

This paper formulates the "last-mile forecasting" problem: after a foundation model produces a statistically plausible baseline forecast, an LLM agent revises it using weakly structured business context (holiday effects, campaign plans, external events, historical analogs, expert feedback). The agent maintains a unified forecast workspace, invokes tools to retrieve contextual evidence, and converts reasoning trajectories into explicit revision actions under structural safety constraints.

Why

Time-series foundation models now produce strong zero-shot baselines, but these are rarely the final forecast used in practice. The gap between a statistically good forecast and a deployment-ready one involves domain knowledge that is difficult to encode in the model itself. Prior work on LLM agents for time series (TS-Agent, ChatTS) focused on reasoning and understanding rather than forecast correction.

How

The system wraps around an existing forecasting backbone (any TS foundation model). The LLM agent receives the baseline forecast plus a structured description of the forecasting context. It then calls tools to retrieve relevant contextual evidence (e.g., checking for holidays in the forecast window, retrieving historical analogs from similar periods). Based on the evidence, it produces a set of forecast revisions. Safety constraints bound the magnitude of revisions relative to the baseline to prevent unbounded drift.

Solves vs predecessors

TS-Agent (Liu 2025) showed that LLMs can reason over time series via tool calls, but it targeted understanding and analysis rather than forecast improvement. The LLMs-for-TS survey noted that zero-shot foundation models fail on domain-specific distribution shifts. This paper provides the missing piece: a mechanism for injecting domain knowledge into foundation model forecasts at deployment time through structured, tool-augmented revision with safety bounds.

Method vs predecessors

Where TS-Agent calls statistical operators to understand a series, this agent calls contextual retrieval tools to gather business knowledge and applies it as forecast corrections. The key structural difference is the "workspace" abstraction: the agent maintains a running forecast state that it iteratively revises, rather than producing a one-shot analysis. The safety constraints (bounding revision magnitude) have no analog in TS-Agent, which does not modify any output — it only produces analysis.
