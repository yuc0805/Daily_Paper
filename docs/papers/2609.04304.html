Iris: Climbing to the Search Frontier

Liu, Liu, Wang, Qin, Liang, Chu, Chen, Gu, Chuan (AllSpark Research) · arXiv 2026-09-03 · arXiv:2609.04304 · Appears in: Agent

What

Iris-mini and Iris-pro are two search agents trained at 35B-A3B and 397B-A17B scales, released together with the data pipeline and training recipe behind them. Training questions are reverse-constructed from the hyperlink structure of a web corpus: multi-hop chains are authored over an entity graph distilled from a seed page and its out-links, every non-answer entity is rewritten into a descriptive reference so no clue resolves by string matching, and only questions a reference model fails closed-book yet solves once given the supporting evidence are admitted. With inference-time context management enabled the two models reach 82.2/84.8/86.9/52.3 and 88.6/85.1/92.9/56.4 on BrowseComp, BrowseComp-ZH, DeepSearchQA and HLE, all from a single ReAct agent with no sub-agents and no test-time verification.

Why

Open-source search agents have trailed closed systems on multi-hop web benchmarks, and the gap has usually been attributed to model scale or to elaborate inference-time scaffolds with sub-agents and verifiers. Two problems sit underneath. Training data for multi-hop search is scarce and, when generated naively, is solvable by string matching rather than by search, so it teaches the wrong behaviour. Separately, published comparisons rarely hold inference-time context management fixed, so reported differences between systems confound the policy with the harness. The paper argues both need addressing before a scale claim is meaningful.

How

Supervised fine-tuning and reinforcement learning alternate in a loop the authors call SFT-RL climbing, where the hardest solved and most efficient rollouts of each RL round are returned to the next supervised pass. Trajectories are filtered at both the trajectory and the turn level before supervised training. Reinforcement learning runs against live search rather than a static corpus, with the reward judge and the observation summarizer served inside the training cluster, and over-long rollouts interrupted at the request level and resumed from their committed prefix at the next step. Every benchmark is then evaluated both with and without inference-time context management, holding the tool set, the context limit and the judge fixed.

Builds on

  • DeepEyesV2 (Hong 2026)Agentic model that interleaves tool calls with reasoning inside a single policy, the architecture Iris scales up.
  • LATS (Zhou 2024)Obtains search-agent capability from tree search over language-agent trajectories at inference time, the cost Iris moves into training.
  • DeepSeek-R1 (2025)Established that outcome-reward RL alone produces long-horizon reasoning without step-level supervision.

Solves vs predecessors

LATS buys capability at inference time by expanding a search tree over candidate trajectories, which is affordable in a benchmark run and not affordable per user query. Iris moves that expenditure into the weights and then runs a single ReAct pass, on the reasoning that expensive exploration can be paid for once during training. The second failure it addresses belongs to the evaluation literature rather than to any single predecessor: because inference-time context management is usually neither held fixed nor reported, the measured gap it produces is larger than most reported differences between competing systems, which means a substantial share of published agent rankings may be tracking the harness rather than the policy.

Method vs predecessors

Against DeepSeek-R1 the difference is the environment. R1 optimises against a verifier on a fixed answer set, where the reward is stationary and rollouts are bounded; Iris optimises against live search, which is nonstationary and where rollouts run long enough that the training loop needs its own systems work, hence serving the judge and summarizer inside the cluster and resuming interrupted rollouts from a committed prefix. Against LATS the difference is where the search happens, at training time inside the data-generation loop rather than at inference over a tree. The data construction is also inverted relative to standard practice: rather than collecting questions and finding evidence, the authors start from an evidence graph and author questions backward over it, then filter to those a reference model cannot answer closed-book, which makes memorisation an explicit exclusion criterion rather than a hoped-for property.
