LycheeMemory V2: Efficient Long-Term Memory for LLM Agents via Semantic Segment-Level Consolidation

Li, Liu, Wang, Huang, Li, Jia, Hu, Zhang · arXiv 2026-08-13 · arXiv:2608.12990 · Appears in: Agent

What

LycheeMemory V2 is a long-term memory framework for LLM agents that replaces turn-level consolidation with semantic segment-level consolidation. Rather than calling an LLM after every interaction to extract and update memories, it batches several exchanges into a segment and encodes each finalized segment into context-independent typed memory records, which are then organized with lightweight structured indexes for query-planned evidence retrieval.

Why

Existing memory systems consolidate eagerly, invoking an LLM after each interaction, so construction cost grows without bound as a conversation lengthens. The two obvious escapes both fail. Coarse summarization lowers construction cost but discards the fine-grained contextual evidence that later queries need. Larger retrieval contexts or multi-hop reasoning at query time keep the evidence but move the same overhead to inference. The Memory Mechanisms Survey in this library maps the design space of what to retain, but leaves open the question of the granularity at which retention should happen, which is the variable this paper isolates.

How

Semantic boundary detection decides where one segment ends and the next begins, which preserves coherent event-level and temporal evidence better than fixed-window batching does. Each finalized segment is encoded once into typed records that are independent of the surrounding context, so retrieval does not need to reconstruct the original conversation. Segment-level batching lowers the frequency of LLM encoding calls, and structured indexes keep query planning cheap. Using GPT-4.1-Mini, the system reports 89.22 percent on LoCoMo and 92.20 percent on LongMemEval-S. Against A-Mem it reduces construction tokens by 86.0 percent on LoCoMo and 75.9 percent on LongMemEval-S, without increasing query-time token usage.

Solves vs predecessors

The survey catalogues what an agent should remember but does not resolve when consolidation should run, so implementations default to per-turn, which is the setting whose cost this paper shows to be avoidable. LATS spends additional LLM calls during retrieval to search over context, which keeps write cost low and makes every query expensive. LycheeMemory fixes the specific failure that both leave standing, namely that the accuracy-cost curve is treated as a function of what is retained when it is also a function of the granularity at which retention happens. Moving consolidation to segment boundaries removes most write-time calls while keeping query-time usage flat, so neither end of the pipeline absorbs the saving.

Method vs predecessors

Compared with eager per-turn consolidation, the unit of work changes from one exchange to one semantically bounded segment, and the output changes from incrementally updated summaries to context-independent typed records. Compared with LATS, the search machinery moves from query time to write time and becomes an indexing step rather than a tree expansion, which is why query-time tokens do not rise. Compared with fixed-window batching, the only difference is boundary placement, and the paper attributes its retention of event-level and temporal evidence to that choice specifically. All results come from a single backbone, GPT-4.1-Mini, on two conversational benchmarks, so the size of the saving at other model scales is untested.
