Chain-of-Experience for Continual LLM Improvement

Tu, Fang, Wang, Xie, Yan (UCSC-VLAA) · arXiv preprint 2026 · arXiv:2608.18027 · Appears in: Agent

What

Chain-of-Experience studies how much a language model improves when it is allowed to accumulate experiential traces across repeated attempts at a task at inference time, rather than being scored on a single zero-shot pass. Feedback comes either from the model itself or from the environment, such as a correctness signal or a public coding test pass rate. Across eight models including GPT-5, Gemini-2.5 Pro and Claude-4.5 Sonnet, on math, coding and knowledge tasks, iterating on experience beats the feedback-free baseline by 5.6% overall while cutting API cost by 19%, and delivers higher accuracy per token than existing test-time strategies.

Why

Standard evaluation asks a model to answer once and records whether it was right, which measures a capability humans do not have and ignores one they do: getting better at a task by doing it repeatedly. If models improve substantially from cheap self-feedback, then single-pass benchmark numbers understate deployed performance, and the interesting engineering question moves from prompt design to feedback-loop design. Prior test-time compute work spent the budget on search within one episode rather than on sequential episodes, so the comparison had not been made on equal cost terms.

How

The setup instantiates the loop with several feedback mechanisms and runs it for multiple iterations per task, carrying the accumulated traces forward as context. Feedback channels are varied and combined: model self-feedback, correctness signals, and coding test pass rates. Findings beyond the headline gain: combining complementary channels adds further improvement, base model ability correlates positively with improvement capacity, models remain robust when feedback is weak or spurious, different channels contribute to different aspects of improvement, and most of the gain arrives in the early iterations.

Builds on

  • Chain-of-Thought Prompting (Wei 2023)Structured the reasoning trace inside one attempt; this work carries the trace across attempts and makes it the input to the next one.
  • Rethinking Memory Mechanisms of Foundation Agents (Huang 2026)Catalogued agent memory mechanisms; this work measures what a plain append-only experience log actually buys.
  • LATS: Language Agent Tree Search (Zhou 2024)Spent test-time compute on branching within one episode; this work spends it on sequential episodes and reports better accuracy per token.

Solves vs predecessors

Tree-search methods such as LATS improve quality by expanding and backtracking inside a single episode, which multiplies token cost and needs a value estimate to guide expansion. Chain-of-Experience reports a lower-cost alternative: sequential retries with an accumulated trace, at 19% lower API cost than the feedback-free baseline rather than a multiple of it. It also addresses a gap left by the memory survey, which described mechanisms without establishing which feedback signals are worth collecting.

Method vs predecessors

LATS maintains a tree of partial trajectories with a value function and a selection policy. Chain-of-Experience maintains a flat, append-only record of prior attempts and their feedback, and re-prompts on it. The simpler structure is the point: no value model, no search policy, and a robustness result showing the loop still helps when the feedback signal is weak or spurious, which a value-guided search would be more sensitive to.
