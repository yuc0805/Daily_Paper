Code as Worlds: Agentic Discovery of Executable World Representations for Physical Reasoning

Wang, Cai, Chen, Chi, Sun, Dai, Hung, Guo, Liu, Long, Duan, Gao, Lyu, Liu, Wu (MirroS Lab) · arXiv 2026-08-27 · arXiv:2608.27549 · Appears in: World Model / RL

What

Code-as-World represents a physical scene as executable code rather than as pixels or as a learned latent vector. Object composition, governing dynamics and visual appearance are all expressed as a program, which makes the representation compact, quantitatively grounded and runnable forward to answer questions about how the scene evolves or how it responds to an intervention. To recover such a program from a video or a natural-language description, the paper runs an agentic loop modelled on abductive reasoning: an agent proposes a candidate world program, executes it, renders the result, verifies it against the observation, and refines. Verified programs then serve as scalable physical supervision for training a vision-language model, and the resulting Code-as-World-VL reaches state of the art on the QuantiPhy benchmark, above leading proprietary models. Weights are released at 4B and 9B.

Why

Vision-language models can recognise and describe physical events but lack explicit representations of the mechanisms underneath: object states, physical parameters, and the dynamics that govern how a scene changes. Without those, a model can describe what it sees and still answer incorrectly about what happens next or what would happen under an intervention, because nothing in its representation is a quantity that can be propagated. The paper's framing is that a pixel observation is evidence about a world rather than a specification of it, recording how the scene appeared from one viewpoint at one moment without saying what exists, how it is structured, or what governs it. The practical consequence is a data problem: quantitative physical supervision is expensive to annotate, and there is no way to generate more of it from raw video if the representation is not something that can be checked.

How

The agentic discovery loop is the mechanism. Given a multimodal observation, the agent writes a program that claims to describe the underlying world, runs it, renders the resulting scene, and compares the rendering to the observation; a mismatch drives a revision of the program, and the cycle repeats until the hypothesis is verified or abandoned. This is abduction in the strict sense, inference to an explanation that would have produced the evidence, and it is made tractable because the explanation is executable and therefore checkable by running it rather than by asking a model whether it looks right. Programs that pass verification are retained, which converts abundant unlabelled observation into labelled physical data with explicit states, parameters and dynamics. Those verified worlds are then used to train the vision-language model on quantitative physical reasoning, so the supervision scales with available video rather than with annotation budget.

Solves vs predecessors

Ha and Schmidhuber compressed observations into a latent state and rolled it forward, which works for control but leaves the representation unreadable: a latent vector cannot be checked against physics, queried for a specific parameter, or edited to pose a counterfactual. Vafa then showed the sharper problem, that accurate next-step prediction does not imply a coherent world model, and diagnosed it without offering a construction that would prevent it. Code-as-World fixes exactly that failure mode by making coherence enforceable rather than measurable after the fact: an executable program either renders to match the observation or it does not, so verification is a program execution instead of a probing experiment. PyVision's loop, meanwhile, produced code that answered a question and was then thrown away, so nothing accumulated; here the code is the representation, which is what allows it to become training data.

Method vs predecessors

The technical shift is from an implicit continuous state fitted by gradient descent to an explicit symbolic program found by search. Ha's latent is learned end-to-end and its quality is only visible through downstream reward; the program here is discovered by an iterative propose-execute-render-verify cycle where each round has a concrete pass or fail signal, so the search is guided by rendering error rather than by task return. Relative to PyVision the agent's output changes status from a transient tool to a persistent artifact, which is what turns the loop into a data engine rather than an inference-time trick. The remaining question, and the one a close read should target, is coverage: rendering agreement verifies that a program is consistent with the observed evidence, not that it is the correct mechanism, so distinct programs can pass on the same video and the supervision inherits whatever bias the proposal distribution has.
