MemReread: Enhancing Agentic Long-Context Reasoning via Memory-Guided Rereading

Ji, Weng, Li, Tang, Lou, Zhang · arXiv 2026-05-11 · arXiv:2605.10268 · Appears in: Reasoning

What

MemReread is a framework for reasoning over long documents at linear cost. It reads the document as a stream and keeps a running memory, but when that memory cannot answer the question it decomposes the question into sub-questions and rereads the relevant source text, recovering indirect facts dropped during the first pass. A reinforcement learning stage improves how far the method extrapolates beyond training context length and decides how many rereading passes each question needs, so easy questions stay cheap and hard ones get more passes.

Why

Reasoning over long documents without the quadratic cost of full attention is hard. Streaming-memory agents read chunk by chunk and update a running memory, but updates overwrite earlier content, so evidence that matters later is lost. Adding a retrieval module to recall discarded text helps only partially: retrieval loses evidence at memory-formation time and is thrown off by queries that do not match what was stored. The paper's motivation is to get non-linear reasoning over long input while keeping linear time complexity and without relying on a fragile retrieval step.

How

The method keeps the streaming reader but removes intermediate retrieval. It builds a final memory in one pass; when that memory is insufficient, it decomposes the question and rereads the relevant parts of the source, which lets the model jump back to earlier text while preserving the document's logical order. A reinforcement learning controller sets the number of rereading passes from task complexity and improves length extrapolation, keeping the added cost bounded. The paper reports consistent gains over baseline long-context frameworks while maintaining linear time complexity in context length.

Solves vs predecessors

The Memory Mechanisms Survey (Huang 2026) describes how agents store, update, and retrieve memory and identifies retrieval-based recall as lossy. MemReread fixes that specific failure mode: rather than retrieving from a compressed store, it rereads the raw source on demand, so evidence overwritten during memory formation can still be recovered. It removes the retrieval module entirely instead of trying to make retrieval less lossy.

Method vs predecessors

Compared to Chain-of-Thought, which produces a single forward reasoning trace in token space, MemReread reasons non-linearly by triggering question decomposition and rereading when the running memory is insufficient, and it adds a reinforcement learning controller that Chain-of-Thought lacks to decide how many rereading passes to spend. Compared to the decomposition-planning agents ADaPT and LATS in your library, MemReread decomposes a question to decide what to reread rather than to plan a sequence of actions.
