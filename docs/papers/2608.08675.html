Efficient Test-Time Scaling for LLM-based Time Series Forecasting (SCALER)

Anonymous et al. · KDD 2026 · arXiv 2026-08-11 · arXiv:2608.08675 · Appears in: Signal/Time Series

What

SCALER is a two-stage coarse-to-fine framework for long-horizon forecasting with a pretrained language model. A lightweight non-LLM forecaster first predicts a coarse future shape at low resolution, and the language model then refines that shape into a full-resolution forecast through a fixed number of multi-scale residual passes. Because the model is handed an explicit numeric shape target instead of a long natural-language description of the series, it processes substantially fewer tokens at each refinement step, and because the refinement schedule is fixed in advance, no reward model is needed to select among sampled trajectories. The authors report improvements over strong baselines on long-term, short-term, and zero-shot benchmarks with average inference roughly 7 times faster than standard test-time-scaling forecasters.

Why

Most language-model forecasters still treat forecasting as a single sequence-to-sequence pass, producing the whole horizon in one inference with no intermediate step the model can correct. The obvious fix, borrowing test-time scaling from reasoning, has been costly in this setting for two separate reasons: long description prompts make every additional pass expensive, and reward-model-based selection over sampled trajectories adds a second model to the inference path. Iterative refinement without an anchor also amplifies shape mismatch, so more compute does not reliably buy more accuracy.

How

The series is encoded at several patch scales. Stage one trains a small global forecaster to produce a coarse shape for the whole horizon, supervised with a shape loss at the lowest resolution. Stage two runs a fixed number of refinement steps, each conditioned on the current estimate and the multi-scale patch encoding, with the language model predicting residual corrections at progressively finer resolution rather than regenerating the forecast. The fixed-step schedule means inference cost is known in advance and does not depend on how many samples a verifier would need to rank.

Builds on

  • Time-LLM (Jin 2024)Established that a frozen language model can forecast once the series is reprogrammed into prompt tokens; SCALER keeps the frozen model and replaces the prompt with a numeric shape.
  • GPT4TS (Zhou 2024)Showed a frozen pretrained transformer generalises across time-series tasks with light input and output adaptation, but in a single forward pass.
  • TTT for Abstract Reasoning (Akyurek 2024)Established that spending compute at inference rather than at training recovers large gains; SCALER imports the idea without the per-instance gradient steps.
  • ChatTS (Xie 2025)Community 4 anchor for language-model-native multivariate series handling through description prompts, the cost SCALER removes.

Solves vs predecessors

Time-LLM and GPT4TS both commit to a single pass, so a bad early token has no correction path and the accuracy ceiling is set by that one decode. SCALER gives the model several chances to correct a forecast that a cheap model has already anchored, which is what turns extra inference compute into accuracy rather than into drift. ChatTS made the prompt the carrier of series semantics, which ties inference cost to prompt length and makes any iterative scheme expensive; SCALER moves that information into a coarse-shape vector, which is the specific change that produces the reported 7x speedup rather than a modest constant-factor saving.

Method vs predecessors

The earlier work in this line changes what the language model reads. SCALER changes how many times it reads and what it writes: residual corrections at increasing resolution, rather than a forecast. Compared with TTT for Abstract Reasoning, which scales test-time compute by adapting weights for each instance, SCALER scales it by adding resolution levels, so there are no gradient steps at inference and the budget is fixed rather than adaptive. Compared with reward-model-based test-time scaling, the fixed-step schedule removes the verifier from the inference path entirely, which is where a large part of the cost saving comes from.
