Aspire: Can Models Self-Evolve from Vague Goals?

Wu, Zhang, Shi, Zhang, Lei, Zhou et al. (ByteDance Seed) · arXiv 2026-08-31 · arXiv:2608.31111 · Appears in: Agent

What

ASPIRE is a benchmark in which the agent receives only a natural-language capability goal, such as "improve at research", with no downstream task and no metric. The agent must interpret the goal, identify its own capability gaps, choose data and an update method, build its own training and validation signal, and decide when it has finished. Evaluation is held out: 520 expert-authored items across six goals, hidden from the agent. Both model-weight evolution and agent-harness evolution run in one interactive environment. Agents reliably complete training and harness-editing loops, but weight-level gains are sparse and unstable, the strongest evolved harness stays below the engineered Qwen-Agent reference, agents often train on mismatched data, and continued search can erase earlier improvements.

Why

Work on LLM self-evolution almost always starts from a task and a metric that a human wrote down, which reduces self-evolution to optimising a given objective. Human learning does not usually start there. The part that is hard, and the part the existing setups skip, is deciding what to learn and how to know whether learning happened. Without a benchmark that withholds the objective, a self-evolving system can report improvement on a proxy it selected itself, and there is no way to tell that apart from real capability gain.

How

The environment gives the agent a goal string and tools, and lets it act: gather or generate data, run updates on weights, or edit its own harness. The agent constructs whatever validation it wants. Scoring happens afterwards on the hidden expert set, so the gap between the agent's self-reported progress and the held-out score is itself a measurement. The reported dynamics are the interesting part: search effort is redirected toward interpreting the goal rather than toward optimising it, self-evaluations are narrow, and because the agent cannot see the hidden set it has no stopping signal, so later search overwrites earlier gains.

Solves vs predecessors

The failure mode ASPIRE exposes is proxy substitution. Every prior self-evolution result is reported against a metric the experimenter supplied, so an agent that improves on that metric is improving on the thing that was asked for by construction. ASPIRE withholds the metric, and the reported outcome is that agents pick proxies that do not transfer: local gains on self-built validation do not appear on the hidden set. Relative to LATS, which searches trajectories against a scorable objective, the limitation removed is that the scorer was assumed to exist. Relative to Repo-To-Skill, which showed a large gain from verified external skills on a fixed harness, ASPIRE isolates what that verification was doing, since without it the same style of harness editing produces unstable results.

Method vs predecessors

Prior self-evolution environments hand the agent a task distribution and score it on a held-out slice of the same distribution. ASPIRE hands it a sentence and scores it on an expert-authored set that the agent never sees and cannot approximate by sampling, which converts goal interpretation from a preprocessing step into the main object of study. It is also unusual in placing weight-level updates and harness-level edits in one environment under one goal, so the two routes to improvement compete for the same budget rather than being studied separately. The engineered Qwen-Agent reference serves the role that a mean baseline serves in a prediction benchmark: a floor that a self-evolving system ought to clear and currently does not.
