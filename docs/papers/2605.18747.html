Code as Agent Harness

Ning et al. · arXiv 2026 · arXiv:2605.18747 · Appears in: Agent

What

This position-and-survey paper reframes code as the substrate that connects an agent to reasoning, action, environment modeling, and execution-based verification, rather than treating code only as an output to be generated. It organizes the design space into three layers: the harness interface, harness mechanisms (planning, memory, tool use, and feedback-driven control for long-horizon execution), and scaling.

Why

Agent systems increasingly use code for more than producing programs: code calls tools, models the environment, and verifies results by execution. Prior work treated these uses separately (tool calling, code generation, memory) without a unifying account, which makes it hard to reason about what a reliable agent harness needs.

How

The paper surveys and organizes existing systems around the three layers above, describing how code links the agent to its world at the interface layer, how planning, memory, tool use, and feedback control operate at the mechanism layer, and what changes at scale. It is a structuring contribution rather than a single new model.

Builds on

  • ToolkenGPT (Hao 2024)Made tools callable by LLMs as learned token embeddings; an early form of the tool-use mechanism this paper generalizes.
  • PyVision (Zhao 2025)Let an agent write and run vision code on the fly; an instance of code as the operational substrate.

Solves vs predecessors

ToolkenGPT and PyVision each solved one slice (callable tools, dynamic code execution) but left the larger picture fragmented. This paper extends the graphify bridge between them (tool-using agents) by treating code as the single harness that unifies tool use, memory, and execution-based verification, addressing the "no common account of the agent substrate" gap.

Method vs predecessors

Where ToolkenGPT contributes a tool-embedding method and PyVision a dynamic-tooling system, this paper contributes a framework that places both inside a layered harness view, moving from "agents that call tools" toward "code as the operating layer the whole agent runs on."
