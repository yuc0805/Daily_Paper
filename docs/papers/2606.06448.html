Agent Memory: Characterization and System Implications of Stateful Long-Horizon Workloads

Authors et al. · arXiv 2026-06 · arXiv:2606.06448 · Appears in: Agent

What

The paper characterizes how long-horizon LLM agents store, retrieve, and update memory across sessions, from a systems rather than a modeling angle. It groups existing memory systems into patterns — flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows — and measures their runtime behavior, surfacing the cost and latency implications of each, such as how memory size and retrieval strategy affect serving.

Why

Most agent-memory work argues about what to remember and how to structure it, but says little about what those choices cost to run at scale. As agents take on long-horizon tasks, the serving cost of memory becomes a deployment constraint that modeling-only studies miss.

How

The authors taxonomize deployed memory systems into a small set of patterns and profile their runtime behavior, relating memory size, retrieval strategy, and control flow to latency and serving cost. The result is a map of the design space backed by measurements of which patterns are expensive.

Solves vs predecessors

The Memory Mechanisms Survey organizes memory designs by what they do but does not say what they cost when deployed. This paper fixes that gap by profiling the same families at runtime, so a design that reads well on paper but is too slow or too large to serve can be identified before deployment.

Method vs predecessors

Compared with the survey, the work keeps the same broad categories but adds a systems methodology: runtime measurement of cost and latency rather than a conceptual taxonomy. It complements the modeling literature with a deployment view.
