ExpWeaver: LLM Agents Learn from Experience via Latent RAG

Feng, Luo, Xu, Hua, Xie, Yang, Liu, You · arXiv 2026-05-31 · arXiv:2606.01041 · Appears in: Agent

What

ExpWeaver encodes agent experiences as hidden states in the LLM's own representation space, retrieves relevant experiences in latent space at each decoding step via cross-attention, and integrates them through gated residual mechanisms. The entire pipeline is optimized end-to-end with reinforcement learning, eliminating the need for a separate RAG module. It achieves state-of-the-art on 12 of 13 diverse tasks (QA, reasoning, coding, scientific prediction, recommendation) while maintaining token efficiency comparable to non-retrieval baselines.

Why

Experience learning for LLM agents currently operates in explicit text space: past interactions are retrieved by semantic similarity and concatenated into the context window. This creates 1.5-2x token overhead and decouples retrieval from generation, meaning the two components are optimized separately with no gradient flow between them. The decoupled architecture also forces a fixed retrieval-then-generate pipeline that cannot adapt retrieval to the generation state at each step.

How

ExpWeaver stores experiences as the LLM's own hidden-state vectors rather than as text. At each decoding step, a cross-attention mechanism queries the experience memory in latent space, aggregates relevant experiences, and injects them into the generation process via a gated residual connection. Because the entire system — encoding, retrieval, and integration — uses the LLM's own representations, it can be trained end-to-end with RL. The framework supports both generative and ranking tasks without architectural changes.

Solves vs predecessors

The Memory Mechanisms Survey (Huang 2026) identified that existing agent memory systems either store experiences as raw text (high token cost, retrieval-generation decoupling) or as fixed embeddings (no end-to-end optimization). ExpWeaver solves both failure modes simultaneously: experiences are stored as the LLM's own hidden states (no token cost for retrieval) and the entire pipeline is RL-optimized end-to-end (no decoupling). The result is +6.8% over the strongest baseline with no additional context-window consumption.

Method vs predecessors

Where ToolkenGPT (Hao 2024) augments LLMs with tool embeddings that expand the vocabulary, and LATS (Zhou 2024) uses explicit tree search to explore action sequences, ExpWeaver takes a fundamentally different approach: it treats past experiences as a latent memory that is continuously queried during decoding via cross-attention. This is more flexible than fixed tool embeddings (experiences can encode arbitrary interaction patterns, not just tool invocations) and more efficient than tree search (no branching; relevant experiences are retrieved in a single cross-attention step per decoding position).
