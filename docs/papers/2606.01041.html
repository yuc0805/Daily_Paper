ExpWeaver: LLM Agents Learn from Experience via Latent RAG

Authors (see paper) · arXiv 2026 · arXiv:2606.01041 · Appears in: Agent

What

ExpWeaver encodes past agent experiences using the LLM's own hidden states, retrieves relevant experiences directly in latent space at each decoding step through cross-attention aggregation and gated residual mechanisms, and optimizes the full pipeline end-to-end with reinforcement learning. This eliminates the separate RAG module and the token overhead of text-based experience retrieval.

Why

Existing experience-retrieval methods for LLM agents operate in text space: they retrieve past trajectories by semantic similarity and concatenate them into the context window. This causes substantial token overhead and creates a decoupled architecture where retrieval is separated from generation. The text-space bottleneck limits the amount of experience the agent can use and prevents the retrieval process from being optimized jointly with the generation process.

How

ExpWeaver stores experiences as hidden-state representations from the LLM rather than as text. At each decoding step, the model retrieves the most relevant stored representations via a learned similarity function in latent space. Retrieved representations are integrated through cross-attention aggregation and gated residual connections. The entire pipeline — encoding, retrieval, integration, and generation — is optimized end-to-end with RL, so the system learns what to store and how to retrieve it for maximum downstream performance.

Builds on

Solves vs predecessors

The Memory Mechanisms survey (Huang 2026) noted that text-based retrieval creates a bottleneck: the more experience the agent has, the more context tokens are consumed. ExpWeaver solves this by moving retrieval into latent space, where the token budget is constant regardless of the size of the experience store. ToolkenGPT showed that embedding external knowledge into the LLM representation works for tool identifiers; ExpWeaver shows it works for full experience traces, which are richer and more variable.

Method vs predecessors

Compared to standard RAG (which retrieves text chunks and pastes them into the prompt), ExpWeaver retrieves hidden-state vectors and integrates them via cross-attention — no tokens consumed in the context window. Compared to ToolkenGPT, which adds single-token embeddings for tool calls, ExpWeaver handles variable-length experience representations. The end-to-end RL optimization over the full retrieval-generation pipeline is the main difference from both: retrieval is not a separate step but part of the generation objective.
