Agentic Context Management: Solving Agent Memory and Cost by Treating Them as Lifecycle and Architecture Problems

Dadhich · arXiv 2026-07-23 · arXiv:2607.21503 · Appears in: Agent

What

This paper argues that many production agent failures come not from weak reasoning but from poor handling of what sits in the reasoning context: long conversation histories, large prompts, big tool definitions, and growing tool outputs. It reframes memory from a store-and-retrieve problem into a lifecycle it calls Agentic Context Management, with five primitives: architecting, ingesting, scoping, anticipating, and compacting with consolidation. It makes a cost argument that naive accumulation grows token cost with the square of conversation length, crude summarization buys linear cost but drops accuracy sharply, and only validated compaction keeps cost linear while holding accuracy. A reference system reports 92% on LongMemEval and 93.2% on LoCoMo.

Why

As agents run longer, they accumulate history and pay a token cost that grows every turn, and they miss recalls within and across conversations. The common response treats this as storage and retrieval. The paper argues that framing is too narrow, because the hard part is deciding what to keep, how to structure it, when to forget while keeping provenance, and how to compact to a budget, all of which happen continuously rather than at a single store step.

How

The paper defines five primitives. Architecting chooses stores per data type. Ingesting decides what to remember and extracts structure. Scoping decides what is relevant now within an organizational scope hierarchy. Anticipating predicts what will be needed next. Compacting and consolidation shrink context to a budget while preserving what matters. It ties each strategy to a cost curve and argues validated compaction is the only option that keeps cost linear without an accuracy cliff. A reference implementation realizes the five primitives as a multi-tenant service.

Solves vs predecessors

The memory survey treated agent memory mainly as choosing storage and retrieval mechanisms. This paper fixes the failure mode where retrieval-centric memory still lets context grow without bound and cost climb: it adds explicit forgetting with provenance and compaction to a budget, and shows with a cost argument why validated compaction beats raw summarization. It turns memory from a place into a managed process.

Method vs predecessors

Where the survey enumerated mechanisms, this paper prescribes a lifecycle with five primitives and attaches an economic model to each context strategy. The technical difference is the move from a static store-and-retrieve architecture to a turn-by-turn management loop with a token budget, plus reported numbers on LongMemEval and LoCoMo as a reference point.
