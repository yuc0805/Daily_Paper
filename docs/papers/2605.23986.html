MemForest: An Efficient Agent Memory System with Hierarchical Temporal Indexing

Chen, Zhang, Pei, He et al. · arXiv 2026 · link · Appears in: Agent

What

MemForest is a memory framework for long-context LLM agents that treats memory as a write-efficient temporal data-management problem. It introduces MemTree, a time-ordered hierarchical index that replaces full-state rewrites with localized per-node updates. On LongMemEval-S it reaches 79.8% pass@1, best among stateful baselines, with memory-construction throughput about 6 times higher than prior systems including EverMemOS. It is also evaluated on LoCoMo.

Why

Existing agent memory systems carry heavy maintenance cost from two limits: coarse-grained state management and sequential update pipelines. Updates are tightly coupled to LLM inference and often require rewriting the full state, so latency grows as memory accumulates and scalability suffers.

How

MemForest breaks the sequential bottleneck with parallel chunk extraction, decoupling memory construction into concurrent operations. MemTree organizes memory as time-ordered trees rather than flat global summaries, so an update touches only the affected tree paths. Interval summaries capture how state evolves over time while leaves keep concrete evidence at specific timestamps, which preserves temporal fidelity without brute-force rewrites.

Solves vs predecessors

The survey identified full-state rewrites and sequential updates as the practical limit on agent memory. MemForest fixes that failure mode directly: per-node updates make write cost scale with what changed rather than total memory size, and parallel extraction removes the sequential coupling to inference, cutting construction latency.

Method vs predecessors

Where prior systems kept a flat global summary that had to be regenerated on each update, MemForest keeps a hierarchical temporal index and treats summaries, embeddings, and root rows as derived views over persistent canonical facts. Re-scoping (splitting, merging, deleting scopes) then rematerializes only affected trees rather than replaying raw sessions, which is what gives the throughput gain.
