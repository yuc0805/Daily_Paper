MemToolAgent: Leveraging Memory for Tool-Using Agents Based on Environment and User Feedback

See arXiv listing · arXiv 2026 · link · Appears in: Agent

What

MemToolAgent adds a memory loop to a tool-using agent. A memory-extraction module turns past tool calls, outcomes, and user or environment feedback into structured entries; a retrieval module selects a relevant subset before each decision. The aim is to stop the agent from repeating tool-use mistakes.

Why

A tool-using agent that does not remember past results will repeat the same wrong tool choice in the same situation. Prior tool-calling methods treat tool selection as a stateless prediction, with no record of what worked before.

How

The memory-extraction module processes past experiences and feedback into structured memory entries, and a retrieval module dynamically selects a relevant subset of those entries to condition the next tool choice across multi-turn interactions.

Builds on

  • ToolkenGPT (Hao 2024)Represents each tool as a learned token so tool calls are part of generation; MemToolAgent adds an outer memory loop.

Solves vs predecessors

ToolkenGPT made tool selection part of next-token prediction but kept it stateless. MemToolAgent fixes the repeated-mistake failure by conditioning on retrieved memory of past tool outcomes, because a static tool embedding cannot record that a tool failed in a given context.

Method vs predecessors

Where ToolkenGPT encodes tools as fixed token embeddings, MemToolAgent wraps the policy in an extract-then-retrieve memory loop driven by environment and user feedback, turning a stateless selector into a feedback-driven one. This extends the graphify tool-use bridge from ToolkenGPT toward PyVision.
