EnvHarness: Awakening Static Worlds for Agent Learning

Huang, Wang, Han, Yan, Chen, Lee et al. (Google) · arXiv 2026-08-20 · arXiv:2608.19880 · Appears in: Agent

What

EnvHarness is a programmable layer of plug-in components that wraps an existing static agent environment and reshapes how it behaves without editing the environment's own logic, so that every reshaped variant keeps the original verifier. A companion system called EnvRigger treats the target policy as a black box, observes its execution trajectories, diagnoses recurring flaws, synthesises harness components aimed at those flaws, and validates each one with fresh rollouts. Across five benchmarks in four domains the harnessed environments beat both the original environments and domain-specific environment generation pipelines, reaching up to a 9.0-point gain on held-out instances while using 9.8% fewer execution steps, and the authors report that the harnessed environments also supply a better optimisation signal for reinforcement learning.

Why

Agent training environments are hand-built and then frozen. They are blind to the specific weaknesses of the policy being trained, and they stop supplying useful gradient once the agent has saturated them. Existing environment generation work addresses part of this but requires a separate pipeline per domain, depends on verifiers that are either expensive or unreliable, and still produces environments that are static once generated. The gap the paper targets is a mechanism that is domain-general, that keeps a trustworthy reward source, and that keeps changing as the policy changes.

How

The harness operates through the standard environment interface, so it can intercept and reshape observations, transitions and available actions without knowledge of the underlying implementation, and because it never replaces the verifier the reward stays as trustworthy as it was in the original environment. EnvRigger closes the loop: it samples rollouts from the current policy, identifies failure patterns in the trajectories, writes harness components targeted at those patterns, and keeps only the components that survive validation on new rollouts. Repeating this gives continuous co-evolution, where the environment is re-aimed at whatever the policy currently cannot do.

Builds on

  • ADaPT: As-Needed Decomposition and Planning (Prasad 2023)Source of the diagnose-failure-then-restructure loop, applied there to task decomposition rather than to the environment.
  • LATS: Language Agent Tree Search (Zhou 2024)Established environment feedback as the value signal for agent search; EnvHarness makes that environment mutable.
  • Offline Reinforcement Learning Tutorial (Levine 2020)Framed limited task and data coverage as the ceiling on policy improvement, which is the constraint EnvHarness attacks.

Solves vs predecessors

ADaPT diagnosed agent failure and changed the task decomposition in response; its failure mode is that no amount of re-splitting helps when the environment simply cannot present the situation the agent is weak on. LATS searched hard against a fixed environment; its failure mode is that search returns nothing once the environment has been saturated. EnvHarness fixes both by moving the intervention point to the environment itself, and it does so without giving up reward trustworthiness, which is the failure mode of naive environment generation: generated environments usually come with generated verifiers that cannot be trusted. Keeping the original verifier while reshaping everything else is the specific design choice that makes the result usable as an RL signal.

Method vs predecessors

ADaPT and LATS both operate inside the agent, on plans and on search trees respectively. EnvHarness operates outside the agent, as a wrapper on the environment, and its optimisation target is a set of executable plug-in components rather than a policy or a search procedure. Compared with domain-specific environment generation pipelines, which rebuild an environment from scratch for one domain, EnvHarness composes over a standard interface and therefore transfers across the four domains tested without per-domain engineering. Compared with the offline RL framing, where coverage is a fixed property of collected data, coverage here is manufactured on demand by a second system reading the policy's own trajectories.
