ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL

Pan, Pei, Lu, Lin, Zhao, Yin, Sun (Tencent) · arXiv 2026-08-28 · arXiv:2608.28476 · Appears in: Agent

What

ContextPilot trains a language agent to edit its own working context while a long-horizon task is running. It widens the editing toolset beyond the usual search, delete and summarize to include global planning, long-term memory writes and soft context offloading, and then trains those editing actions with a reinforcement learning procedure built for the problem rather than borrowed from answer-level training. Context and entropy variation identify which editing decisions actually change the outcome, branch sampling is concentrated at those points, and the advantage for a given edit is estimated from all branched trajectories that pass through it. Reported outcome is stronger performance on long-context question answering and deep search while holding a smaller working context, across several base models and benchmarks; weights are released as ContextPilot-8B and ContextPilot-14B.

Why

A long-horizon agent has to retrieve, integrate and maintain information scattered across many turns, and keeping the full interaction history makes the working context grow without bound until it exceeds the window or dilutes the useful content. Recent proactive context management lets a model edit its own context with tools, but three problems remain. The toolset is narrow, offering no way to record a global plan, commit something to long-term memory, or compress adaptively rather than by deletion. Exploration treats every context action as equally worth sampling even though most edits are inconsequential and a few decide the trajectory. And credit assignment is coarse: a single trajectory-level reward is spread across every intermediate edit, so an edit that discarded the critical evidence receives the same signal as the twenty harmless edits around it.

How

The toolset is augmented first, adding planning, long-term memory and soft context offloading so that compression is not forced to be deletion. For training, the method watches context and entropy variation across the trajectory to find the editing decisions where the model's subsequent behaviour is sensitive to the choice, and treats those as branch points. From each branch point it samples multiple continuations, so the same intermediate context snapshot is followed by several downstream outcomes. The advantage assigned to that specific editing action is then estimated from the outcomes of all branches passing through it, which gives an action-level rather than trajectory-level signal and removes most of the variance that flat credit assignment introduces. Evaluation is on long-context question answering and deep search, and the comparison is made at matched or smaller context size so the gain cannot be attributed to keeping more.

Solves vs predecessors

The Memory Mechanisms survey establishes that agents need designed memory but does not say when to write or when to drop, leaving the policy to heuristics. ToolkenGPT learns which external tool to call and treats the context as the medium those calls live in, never as an object to be acted on. The failure mode ContextPilot fixes is the one both leave open: with a single trajectory-level reward, an agent cannot learn that one particular deletion four turns ago is what caused the wrong answer, so it never learns a selective retention policy and instead either keeps everything or summarizes uniformly. Estimating advantages per editing action from branched outcomes makes that attribution possible, which is what allows the reported performance gain to come with a smaller rather than larger context.

Method vs predecessors

LATS builds a tree over trajectories and uses it to search for a better answer at inference time, paying the branching cost on every query. ContextPilot builds the same kind of tree but only during training, and only at the small subset of decision points flagged by entropy and context variation, then discards it; what survives is a policy that makes the right edit in a single forward pass. Relative to ToolkenGPT the action space moves inward, from calls that fetch new information to operations that restructure information already held, which changes what a reward means: the objective is no longer only task success but task success under a context budget. The entropy-variation criterion for selecting branch points has no direct predecessor in the library and is the piece most worth checking, since the whole efficiency argument rests on consequential edits being rare and detectable.
