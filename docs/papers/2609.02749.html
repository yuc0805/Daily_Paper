Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills

Chen, Hu, Qian, Liu, Wei, Chen, Lian, Dou, Li, Ye, Liu (BAAI) · arXiv 2026-09-02 · arXiv:2609.02749 · Appears in: Agent

What

The paper names a layer that autonomous research agents lack, which it calls operational knowledge: the know-how separating knowing a method from making it work. DisCo is a research agent that both creates and consumes such knowledge, distilling it in a task-agnostic pass over widely used repositories and a task-oriented pass for the job at hand. The task-agnostic pass over 1,000 repositories yields the AREX-Skill Library, more than 5,000 verified skills organised into 20 areas and 178 capability families. Holding the GPT-5.5 backbone, the research harness and the downstream execution budget fixed, the skill-equipped agent scores 134.3 percent higher on MLE-bench, 34.4 percent higher on PaperBench, 9.2 percent higher on FrontierCS and 14.0 percent higher on PassNet than the same agent without skills.

Why

Current agents pair a model backbone with a harness for planning, execution, memory and verification, and that architecture leaves domain-specific know-how outside the system. The knowledge is not missing from the field — it sits in repositories and papers — but it is written for human readers and is far too large to load into context during a task, so an agent rediscovers it on every run or fails silently by getting a detail wrong. Prior harness work improved planning and verification without addressing the content those mechanisms operate on, and prior memory work made the agent remember its own runs, which helps only after it has already met a similar problem.

How

Distillation compresses a repository into compact skills, each verified before entry into the library, so the artifact is a checked procedure rather than a summary. The task-agnostic form runs offline across the open ecosystem and produces reusable entries organised by capability family; the task-oriented form runs during a task and produces the specific skills that task requires. Because the evaluation holds backbone, harness and execution budget constant and varies only skill availability, the reported gains isolate the contribution of the distilled operating context rather than of a stronger model or a longer run.

Solves vs predecessors

The failure mode fixed is rediscovery. Under the memory framing inherited from Huang 2026, an agent's useful knowledge is whatever it accumulated in the current or a similar past run, so a first encounter with a method costs full rediscovery and a subtly wrong configuration produces a plausible but broken result with no signal. DisCo removes that dependency by making the knowledge available before the first encounter and verified before use. Relative to ToolkenGPT, the limitation removed is narrower and sharper: knowing the call signature does not tell an agent which settings make the method work, and it is the settings that decide whether an ML task succeeds.

Method vs predecessors

ToolkenGPT put the compression in the parameters, learning an embedding per tool, which requires training and binds the knowledge to a checkpoint. DisCo puts the compression in text, producing artifacts that any backbone can read, which is why the evaluation can hold the backbone fixed and vary only the library. Against the memory line of work, the difference is direction of flow: episodic memory is written by the agent and read by itself later, while a skill library is written once by a distillation process and read by many agents on unrelated tasks, so the unit of reuse changes from a trajectory to a procedure. Verification is the third difference — entries are checked before admission, where episodic traces are not.
