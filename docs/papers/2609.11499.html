Recursive Code World Models: Building Complex Worlds through Recursive Scene Programs

Li, Liao, Zhu · arXiv 2026-09-10 · arXiv:2609.11499 · Appears in: Agent

What

RCWM reconstructs a complex 3D world as executable code from a single reference image. A Recursive Scene Program represents the world as compositional scene code, and a construction solver calls itself: establish the whole, recursively reconstruct the parts that remain unresolved, then revisit the whole to refine how those parts compose. Reference-aligned views propagate one shared camera projection across recursion levels, and a vision-language coding agent compares the reference image against renders to decide whether to refine in place, descend, or return. The paper reports wins over prior code-based image-to-scene reconstruction methods, with ablations indicating that deeper recursive calls improve finer-scale reconstruction.

Why

Code world models make an attractive promise: a world stored as a program is inspectable, editable, and exactly reproducible, unlike a world stored in network weights. The promise stalls on construction. Representing a scene as code says nothing about how to arrive at the code for a scene that is too complex to write in one pass, and a single-pass vision-language agent asked to emit a whole scene program produces something coarse. Attempts to fix this by refining pieces independently create a second problem: each refined piece is locally better and globally inconsistent, because boundaries, spatial relations, and shared errors are invisible from inside a part.

How

The solver is uniform at every level — establish, descend, revisit — so the same procedure handles the room and the object on the shelf. The parent revisitation step is what distinguishes it from ordinary divide-and-conquer: after children return, control goes back to the parent scope specifically to repair boundaries, spatial relations, and errors the children share. Sharing one camera projection across levels keeps every render comparable to the same reference image, so the agent's visual comparison means the same thing at each depth. The agent itself supplies the control signal by diffing reference against render, which is what lets recursion depth adapt to scene complexity rather than being fixed in advance.

Solves vs predecessors

ADaPT decomposes a task on demand and returns once the subtasks succeed, which is correct when subtasks are independent and wrong when they share a boundary. That is the failure this paper targets: in scene construction, solving the parts well leaves the composition broken, and no amount of further local refinement repairs it because the inconsistency is not visible from within any part. The mandatory parent revisit closes that hole. Against PyVision, the failure addressed is persistence: a per-query script is discarded after it answers, so nothing accumulates, whereas a scene program is the deliverable and every refinement edits it.

Method vs predecessors

ADaPT recursion terminates on subtask success; RCWM recursion terminates only after a return visit to the parent, making the control flow global-local-global rather than top-down. PyVision generates tools; RCWM generates and repeatedly edits a single persistent artifact, with renders as the feedback channel. Compared with Ha's World Models, the simulator lives in source code instead of latent weights, which buys inspectability and editability at the price of a construction problem that the recursion exists to solve. This extends the graphify cross-area bridge from ToolkenGPT to PyVision, which already crossed tool-using agents and vision, pushing it toward tool use that builds a persistent structured artifact. The abstract reports comparative wins without headline numbers, so the magnitude needs the full text.
