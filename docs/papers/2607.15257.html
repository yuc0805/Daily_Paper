SearchOS-V1: Towards Robust Open-Domain Information-Seeking Agent Collaboration

Zhang, Gao, Wu, Fan, Zhang, Ma, Yao, et al. · arXiv 2026 · arXiv:2607.15257 · Appears in: Agent

What

SearchOS is a multi-agent framework for open-domain information seeking. It turns fragile, implicit search progress into explicit, persistent, and shared state. The task is reframed as relational schema completion with grounded citations: agents discover entities, populate attributes across linked tables, and anchor each value to source evidence. Search-Oriented Context Management (SOCM) externalizes the evolving state into four structures — a Frontier Task, an Evidence Graph, a Coverage Map, and a Failure Memory — and a Search Tool Middleware Harness records grounded evidence and reacts to stalls or budget exhaustion.

Why

Tool-using LLM agents can call web search, but as interaction histories grow they lose track of task progress. When searches fail to return useful evidence, single- and multi-agent systems fall into repetitive loops that waste the search budget and leave the final output incomplete. Prior systems keep progress implicitly inside a long context window, which is fragile and hard to share across agents. The paper's aim is to make progress explicit and persistent so failures are not repeated.

How

On top of the four externalized state structures, SearchOS applies a pipeline-parallel scheduler that overlaps sub-agents and continuously refills freed slots with tasks targeting unresolved coverage gaps, raising utilization and throughput. The middleware harness intercepts model-tool interactions to record evidence and provides a reusable hierarchical skill system (strategy and access skills) so failed search patterns are not repeated across runs. On WideSearch and GISA the system leads all reported metrics among the single- and multi-agent baselines evaluated.

Solves vs predecessors

ADaPT and LATS improve how an agent plans and searches, but both keep the record of progress inside the reasoning trace, so a long history causes the agent to lose track and re-issue failed queries. SearchOS fixes the specific failure mode — "the agent forgets what it already tried and loops" — by writing a Coverage Map and a Failure Memory outside the context window, so unresolved gaps and known dead ends are read back explicitly rather than reconstructed from a transcript.

Method vs predecessors

Compared to LATS, which searches a tree of actions at inference time, SearchOS keeps persistent external state that outlives any single step and lets several sub-agents coordinate through a shared Evidence Graph. Compared to the memory-agent line, which keeps a running store for one agent, SearchOS structures the store (schema completion with grounded citations) and adds a scheduler that assigns sub-agents to uncovered gaps. The integration boundary moves from "better reasoning" to "better shared bookkeeping."
