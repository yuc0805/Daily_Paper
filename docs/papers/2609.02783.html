EarlyEval: Cheaper Agent Evaluation via Early Outcome Prediction

Shi, Sun, Dong, Wan, Lo, Gu (SJTU, SMU, ECNU) · arXiv 2026-09-02 · arXiv:2609.02783 · Appears in: Agent

What

EarlyEval reduces the cost of evaluating LLM agents by halting runs whose outcome is already predictable from partial behaviour. A pair of LightGBM classifiers, one trained to recognise eventual success and one eventual failure, read behavioural, textual and reference-solution features at each step, and the run stops the moment either crosses a calibrated confidence threshold. Across SWE-bench Verified, TerminalBench and Toolathlon the method eliminates 13 to 26 percent of agent steps and up to 44.1 percent of input tokens and 29.4 percent of output tokens at 89 to 97 percent prediction accuracy, while per-agent resolve rates shift by only one to two percentage points on average. The per-step overhead of the classifiers is negligible relative to the model calls they replace.

Why

A single pass of a frontier model over an agentic benchmark costs hundreds to thousands of dollars, and that cost recurs on every iteration of development, which makes evaluation rather than training the binding constraint for many groups. Prior efficiency work centres on benchmark distillation: select a smaller representative subset of tasks and run those. That reduces the number of tasks but leaves the cost of each retained task untouched, so the two axes are complementary rather than competing. The observation this paper exploits is that agent trajectories are highly predictive of their own outcomes well before completion, so most of the tail of a run is spent confirming a conclusion already visible.

How

Two classifiers are used rather than one because the decision is asymmetric: stopping early on a confident success and stopping early on a confident failure carry different costs and are better calibrated separately. Features are drawn from three sources — the agent's behaviour, the text it produces, and the reference solution — and the thresholds are calibrated so the induced change in reported resolve rate stays small and quantified. Because the features are behavioural and textual rather than code-specific, the framework is not tied to software-engineering benchmarks, though all three evaluation suites happen to be execution-based.

Solves vs predecessors

The failure mode fixed belongs to benchmark distillation rather than to either named parent: reducing the task count lowers total cost but also lowers the resolution of the estimate, and it does nothing about the fact that a single hard task can dominate the bill. EarlyEval leaves the task set intact, so estimate resolution is preserved, and cuts inside each run instead. Relative to Vafa, the limitation removed is different in kind — Vafa's concern was whether the number means what it claims, and this paper's is what the number costs to obtain, with a stated bound on the distortion introduced.

Method vs predecessors

Where the surveyed agent literature treats a trajectory as something to be run to completion and then scored, this paper treats it as a sequential-decision problem with a stopping rule, which is a change of statistical framing rather than of agent design. The predictors are deliberately small: gradient-boosted trees over engineered features, not a learned critic model, which keeps the overhead below the cost of one additional model call and makes the calibration tractable. The structural move matches Declarative Attention from the same day — spend a cheap predictor to avoid a large amount of work — applied to trajectory steps rather than to context positions.
