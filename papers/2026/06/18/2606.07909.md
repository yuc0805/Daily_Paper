# MemToolAgent: Leveraging Memory for Tool-Using Agents Based on Environment and User Feedback

**Arxiv:** 2606.07909 | **Date:** 2026-06-18 | **Area:** agent

## What it does
MemToolAgent adds a memory loop to a tool-using agent. A memory-extraction module turns past tool calls, outcomes, and user or environment feedback into structured entries; a retrieval module selects a relevant subset before each decision. The aim is to stop the agent from repeating tool-use mistakes.

## Direct parents (in Leo's library)
- [6RDHVVA2] ToolkenGPT — represents each tool as a learned token so tool calls are part of generation (graphify community 0).

## Delta from parents
Where ToolkenGPT made tool selection part of next-token prediction, MemToolAgent adds an outer memory loop so the choice is also informed by past results, because a static tool embedding cannot record that a given tool failed in a given context. This extends the tool-use bridge in the library: ToolkenGPT connects to PyVision (XQTY5MPI) as a graphify cross-area bridge for tool-using agents, and MemToolAgent pushes that bridge toward feedback-driven tool use.

## Why Leo should care
Feedback-driven tool selection is a small, testable change on top of a method he already tracks (ToolkenGPT). It is a clean example of adding state to an otherwise stateless tool-calling policy.
