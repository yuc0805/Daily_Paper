# MetaForge: A Self-Evolving Multimodal Agent that Retrieves, Adapts, and Forges Tools On Demand

**Arxiv:** 2606.01801 | **Date:** 2026-06-23 | **Area:** agent

## What it does
MetaForge is a multimodal agent that does not work from a fixed tool set. When a task needs a capability it does not have, the agent retrieves a related tool, adapts it, or writes a new one, then keeps the result for later use. The design target is open-ended visual and multimodal tasks where the needed operations cannot be enumerated ahead of time.

## Direct parents (in Leo's library)
- [XQTY5MPI] PyVision (zhao2025_pyvision, community 0) — agent that writes Python vision tools at run time instead of calling a fixed library.
- [6RDHVVA2] ToolkenGPT (hao2024_toolkengpt, community 0) — represents tools as learned token embeddings the model can call.
- [4XXXYXS9] DeepEyesV2 (hong2026_deepeyesv2, community 0) — agentic multimodal model that interleaves perception with tool use.

## Delta from parents
PyVision already lets an agent generate vision tools on the fly, and ToolkenGPT and DeepEyesV2 give models flexible ways to select and call tools, but in each case the tool, once made or selected, is used and discarded for that task. Where PyVision forges a tool for the current problem, MetaForge adds a retain-and-reuse loop: forged tools are stored, retrieved, and adapted across tasks, so the agent's tool set grows with experience rather than resetting each time. The claimed change is therefore in tool persistence and self-improvement, not in the act of tool generation itself.

## Why Leo should care
A persistent, self-built tool library is the agent-side analogue of giving a time-series reasoning agent a growing set of analysis operators it can extend itself, rather than a fixed operator menu. The mechanism sits in the same agent community (0) as PyVision and DeepEyesV2 that Leo already tracks for porting.
