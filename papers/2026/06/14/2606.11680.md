# Organize then Retrieve: Hierarchical Memory Navigation for Efficient Agents (HORMA)

**Arxiv:** 2606.11680 | **Date:** 2026-06-14 | **Area:** agent

## What it does
HORMA is a working-memory mechanism for LLM agents on long-horizon tasks. It organizes past experience into a file-system-like hierarchy, where short summarized entities link back to the corresponding raw trajectories, so the agent can reach detail without holding everything in context. The method has two stages: structured memory construction and navigation-based retrieval. The aim is to keep reasoning quality, inference cost, and latency under control as a task runs long.

## Direct parents (in Leo's library)
- [BDY3HUCV] Memory Mechanisms Survey (Huang 2026) — mapped the design space of memory for foundation agents; HORMA is one concrete point in that space.
- [Z9WZPMNU] Agent AI Survey (Durante 2024) — framed multimodal agents that act over long horizons, the setting HORMA targets.

## Delta from parents
Where the Memory Mechanisms Survey laid out compression and similarity-based retrieval as the usual options, HORMA argues both lose the temporal order and causal links that multi-step tasks need, and replaces flat retrieval with a hierarchy that keeps a pointer from each summary to its raw trace. Where the Agent AI Survey described long-horizon agents in general terms, HORMA gives a specific organize-then-retrieve procedure and measures it as a working-memory cost problem rather than a capability problem.

## Why Leo should care
Long-horizon memory is the same problem a continuous physiological monitoring agent would face: it cannot hold weeks of raw sensor data in context, and similarity search over raw windows loses the order of events. HORMA's summary-to-raw pointer structure is a candidate design for that setting and has not been applied to time-series or bio-sensing agents.
