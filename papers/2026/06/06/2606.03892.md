# PROVE: Programmatic Rewards On Verified Environments for Multi-Step Tool Use

**Arxiv:** 2606.03892 | **Date:** 2026-06-02 | **Area:** agent

## What it does
PROVE trains LLMs to orchestrate multi-step tool calls using reinforcement learning against 20 stateful MCP servers exposing 343 tools. It introduces an automated data synthesis pipeline that generates validated multi-turn tool-call trajectories grounded in live server state, plus a multi-component programmatic reward combining validity scoring, dependency-aware coverage, an adaptive efficiency penalty, and argument-value matching. Four models (Qwen3-4B through Granite-4.1-8B) trained with GRPO on 13K examples show gains of up to +10.2 points on BFCL Multi-Turn.

## Delta from parents
Where ToolkenGPT embedded tool identifiers into the token vocabulary and ADaPT/LATS focused on planning and search strategies, PROVE tackles the training data bottleneck: generating realistic multi-turn tool trajectories that actually execute against live stateful servers. The key difference is that PROVE grounds its synthetic training data in real server state (so every generated query references entities that exist), and replaces judge-model rewards with a compact programmatic reward signal. This makes RL training for tool use practical at small scale (13K examples) without requiring an expensive reward model.

## Why Leo should care
The MCP server approach is directly relevant to building research tool pipelines — e.g., an agent that queries Zotero, runs analysis scripts, and writes reports. The programmatic reward design (no judge model needed) is also a useful template for domains where ground-truth verification is available.
