# From Player to Master: Enhancing Test-Time Learning of LLM Agents via Reinforcement Learning over Memory

**Arxiv:** 2606.08656 | **Date:** 2026-06-13 | **Area:** agent

## What it does
The paper introduces MemoPilot, a plug-in "memory copilot" that learns how to update an LLM agent's explicit memory so a frozen base model improves across a long run of interactions. Memory updating is framed as a multi-turn decision problem and trained end-to-end with multi-turn GRPO, using a turn-wise reward and a context-independent, turn-level advantage estimate for finer credit assignment. On two repeated-game testbeds, Rock-Paper-Scissors and Limit Texas Hold'em, MemoPilot ranks first in Elo (1762 on Hold'em, 1590 on RPS) and beats hand-designed memory rules and proprietary models including DeepSeek-V3.2.

## Direct parents (in Leo's library)
- [BDY3HUCV] Rethinking Memory Mechanisms of Foundation Agents (Huang 2026) — surveyed how agents store and update memory, mostly with hand-written rules.
- [Z5IWHZAE] DeepSeek-R1: Reasoning via RL (2025) — showed that GRPO-style reinforcement learning can train multi-step behavior in LLMs.

## Delta from parents
Where the memory survey (Huang 2026) described memory updates that rely on hand-designed prompting rules, this paper makes the update process itself a learned policy. Where DeepSeek-R1 (2025) applied GRPO to a single reasoning trace, MemoPilot extends GRPO to a multi-turn setting and adds turn-level credit assignment so the reward can be attached to the right memory edit rather than to the whole rollout. The change is to treat "what to write into memory" as an RL action optimized for downstream reward, instead of a fixed heuristic.

## Delta cross-area note
This paper extends DeepSeek-R1, which already bridges reasoning-via-RL and chain-of-thought prompting in your library (the deepseek2025_r1 to wei2023_cot bridge). MemoPilot pushes that bridge further: it moves RL credit assignment from a single chain of thought to a sequence of memory edits across turns, so the reasoning-via-RL idea now reaches long-horizon memory control rather than one-shot reasoning.

## Why Leo should care
Memory that updates itself across days is the same problem a long-running patient-monitoring agent would face. The multi-turn GRPO recipe here is not yet applied to time-series or bio-sensing agents, which is a clean transfer target: train the memory-update policy of a wearable monitoring agent so it keeps a useful per-patient state over time.
