# EvoMemBench: Benchmarking Agent Memory from a Self-Evolving Perspective

**Arxiv:** 2605.18421 | **Date:** 2026-06-01 | **Area:** agent

## What it does
EvoMemBench is a benchmark built specifically for agent memory rather than reasoning or planning. It organizes evaluation along axes that include memory scope (within an episode versus across episodes) and how memory must evolve as the agent's situation changes, giving a structured way to rank memory mechanisms under shifting tasks instead of a single aggregate score.

## Direct parents (in Leo's library)
- [BDY3HUCV] Memory Mechanisms Survey (Huang 2026, graphify_id huang2026_memory) — lays out a taxonomy of agent memory mechanisms (store, update, retrieve).

## Delta from parents
Where Huang 2026 describes memory mechanisms qualitatively and names failure modes, EvoMemBench turns that taxonomy into a measurement: it operationalizes store/update/retrieve into scored tasks and runs them under self-evolving conditions, because a survey can name a weakness but cannot rank methods against it. It is the natural test harness for memory methods such as MemReread (2605.10268), featured the same day.

## Why Leo should care
The self-evolving, cross-episode memory axes are a template for a longitudinal bio-sensing benchmark, where a monitoring agent must update its model of one user as their physiology drifts. No benchmark in Leo's library measures memory for an agent over weeks of wearable data; this is an unported opportunity, not a closed-off port.
