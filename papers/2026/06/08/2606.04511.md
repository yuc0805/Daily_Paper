# SparDA: Sparse Decoupled Attention for Efficient Long-Context LLM Inference

**Arxiv:** 2606.04511 | **Date:** 2026-06-03 | **Area:** llm

## What it does
SparDA introduces a fourth per-layer projection called the Forecast, added alongside Query, Key, and Value, that predicts which KV blocks will be needed by the next Transformer layer. This lookahead lets the system overlap CPU-to-GPU prefetch of offloaded KV cache blocks with the current layer's computation. The Forecast uses one head per GQA group, adds less than 0.5% parameters, and is trained only by matching the original sparse selector's attention distribution. On 8B sparse-pretrained models, SparDA delivers up to 1.25x prefill speedup, 1.7x decode speedup, and 5.3x higher decode throughput through larger feasible batch sizes on a single GPU.

## Delta from parents
Where the original Transformer computes attention over the full KV cache at every layer, SparDA decouples the block-selection step from the attention query itself. The Forecast projection at layer L predicts which KV blocks layer L+1 will need, so the GPU can prefetch those blocks from CPU memory while layer L's attention is still running. This is a systems-aware architectural change: it does not alter the attention computation itself but restructures how data flows between CPU and GPU memory to remove the PCIe bottleneck that plagues KV cache offloading at long contexts.

## Why Leo should care
This paper is relevant for anyone running long-sequence inference on a single GPU. The Forecast idea — predicting future data access patterns from the current layer's computation — is architecture-generic and could apply to time-series transformer models where inference on long sensor recordings (tens of thousands of timesteps) is bottlenecked by KV cache. If Leo uses PatchTST or similar patched Transformers for long-horizon forecasting, SparDA's lookahead prefetch could cut inference latency on consumer hardware.
