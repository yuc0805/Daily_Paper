# Code as Worlds: Agentic Discovery of Executable World Representations for Physical Reasoning

**Arxiv:** 2608.27549 | **Date:** 2026-08-31 | **Area:** world-model-rl

## What it does
Represents a physical scene as executable code rather than as pixels or latent vectors. Object composition, governing dynamics and visual appearance are all written as a program, so the representation is compact, quantitative and can be run forward to answer questions about how the scene evolves or responds to an intervention. To recover such a program from a video or a natural-language description the paper runs an agentic loop modeled on abductive reasoning: propose a candidate world program, execute it, render the result, compare against the observation, and refine. Verified programs are then used as scalable supervision for training a vision-language model, and the resulting Code-as-World-VL reaches state of the art on the QuantiPhy benchmark, above leading proprietary models. Weights released at 4B and 9B.

## Direct parents (in Leo's library)
- [938DAXZT] World Models (Ha 2018) — established the learned-latent-dynamics formulation this paper replaces with executable code.
- [P92FLHJ2] Evaluating World Models (Vafa 2024) — showed that a model can predict well while holding an incoherent internal world model, the measurement problem that motivates an inspectable representation.
- [XQTY5MPI] PyVision (Zhao 2025, graphify `zhao2025_pyvision`, Community 0) — agentic vision with dynamically written tools, the propose-execute-verify loop reused here to search over world programs instead of over analysis tools.

## Delta from parents
Where Ha and Schmidhuber compressed observations into a learned latent state and rolled that state forward, this paper writes the state and its dynamics as source code, because a latent vector cannot be read, checked against physics or queried for a specific parameter. Where Vafa showed that good next-step prediction does not imply a coherent world model and left the diagnosis without a construction, this paper makes coherence enforceable: an executable program either renders to match the observation or it does not, so verification is a program execution rather than a probing experiment. Where PyVision let an agent write throwaway analysis code to answer a visual question, Code-as-World has the agent write code that is itself the persistent representation of the scene, so the artifact survives the query that produced it and can be reused as training data. The pipeline is the contribution, since none of the three parents produce supervision.

## Why Leo should care
This is a bridge extension. PyVision sits in Community 0 and is linked to ToolkenGPT in the cross-area bridge list as tool-using agents; the world-model papers in Leo's library sit in Community 7. Code-as-World crosses those two, using an agentic tool-writing loop to build world models, which is a crossing his library does not yet contain. The relevant question for signal work is whether a physiological system admits the same treatment: a cardiac or respiratory model is already written as differential equations, so the propose-execute-render-verify loop has a simulator available in a way image physics does not. That would make synthetic-but-verified biosignal supervision, which is the same scarce-label problem the biosignal foundation-model papers keep running into.
