# ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL

**Arxiv:** 2608.28476 | **Date:** 2026-08-31 | **Area:** agent

## What it does
Trains a language agent to edit its own working context during long-horizon tasks. It widens the context-editing toolset beyond the usual search, delete and summarize to include global planning, long-term memory writes and soft context offloading. It then trains those editing actions with reinforcement learning designed for the problem: context and entropy variation are used to find the editing decisions that actually change the outcome, branch sampling is concentrated at those points, and advantages are estimated per action from all branched trajectories passing through that edit rather than from a single trajectory-level reward. Reported result is stronger performance on long-context question answering and deep search with a smaller working context, across several base models. Weights released as ContextPilot-8B and ContextPilot-14B.

## Delta from parents
Where the Memory Mechanisms survey argued that agent memory should be designed rather than accumulated, this paper makes the memory operations themselves trainable actions with their own reward signal, because naming the axis does not tell you when to write or drop. Where ToolkenGPT learned which external tool to call, this paper learns which internal edit to make to the context itself, treating the working context as the thing being acted on rather than the medium the action lives in. Where LATS branched trajectories at inference time to search for a better answer, ContextPilot branches at training time and uses the outcomes of the branches to assign credit to a specific intermediate edit, which converts LATS's tree from a decoding procedure into a variance-reduction device. The selection of branch points by entropy variation is the piece with no parent in the library.

## Why Leo should care
This is the credit-assignment gap that Tier D has flagged twice for time-series agents. TS-Agent accumulates an evidence log and never prunes it, and Sensor2Text keeps the sensor history in context, so both inherit the growing-context problem this paper attacks. A month of wearable data is a longer horizon than any deep-search benchmark here, and the editing decisions are more consequential because dropping the wrong segment discards a physiological event rather than a web page. The transferable part is the fine-grained advantage estimate, not the toolset: it gives a way to learn which sensor windows are worth keeping in an agent's working context, which is currently done by heuristic downsampling everywhere in the wearable literature.
