# SPADE: Self-Play in Adaptive Synthetic Executable Environments

**Arxiv:** 2608.19197 | **Date:** 2026-08-22 | **Area:** world-model-rl

## What it does
SPADE is a self-play reinforcement learning framework in which one language model plays two roles. As Environment Designer it writes complete long-horizon training environments as executable code with a Gym-style reset and step interface, including state transitions, reward functions and verification code. As Reasoning Agent it learns to act in those environments. The Designer is optimised against the Agent's regret, estimated as the reward gap between running with and without privileged hints, which pushes generated environments to the edge of the Agent's ability while keeping them solvable. At 30B parameters SPADE improves on the strongest fixed-environment baseline by +5.3 on average across eight held-out math, science, code and reasoning benchmarks, by +5.7 on BFCL-v4 multi-turn and by +13.9 on ACEBench-Agent.

## Direct parents (in Leo's library)
- [77ERE7HA] LATS: Language Agent Tree Search (Zhou 2024) — established that an LLM can search over its own action space when an external environment supplies the value signal.
- [ZULLM3UF] Offline Reinforcement Learning Tutorial (Levine 2020) — established that a frozen task or data distribution caps policy improvement.
- [ZNEMGMWY] Sample-efficient Cross-Entropy Method (Pinneri 2020) — established iterative resampling of a candidate distribution toward higher-reward regions as a planning primitive.

## Delta from parents
Where LATS used an LLM to search *within* a given environment, SPADE uses an LLM to write the environment itself, because the authors argue that once the agent outgrows the environment pool no amount of in-environment search adds signal. Where the offline RL tutorial treated distribution coverage as a fixed property of the dataset, SPADE makes the task distribution a second optimised policy with regret as its objective. Where the cross-entropy method resampled a candidate *action* distribution toward reward, SPADE resamples a candidate *task* distribution toward agent regret, which is the same shaping idea moved one level up the hierarchy. The two components the authors identify as necessary, grounding the Designer on documents from a pretraining corpus and giving it accumulated environment memory, are the practical difference between this and earlier synthetic-task generation.

## Why Leo should care
SPADE and EnvHarness landed within a day of each other and answer the same question in opposite directions: SPADE generates environments from scratch, EnvHarness reshapes environments that already exist. Read them together and the shared claim is clear, that the environment is now a trainable object. For bio-sensing the immediate parallel is curriculum construction over recording conditions rather than over labels, which no paper in Community 4 or Community 5 currently does.
