# EnvHarness: Awakening Static Worlds for Agent Learning

**Arxiv:** 2608.19880 | **Date:** 2026-08-22 | **Area:** agent

## What it does
EnvHarness is a programmable layer of plug-in components that wraps an existing static agent environment and reshapes its behaviour without editing the environment's own logic, so the original verifier is preserved. A companion system, EnvRigger, treats the target policy as a black box, reads its execution trajectories, diagnoses recurring failures, and synthesises harness components aimed at those failures, then validates each component with fresh rollouts. Across five benchmarks in four domains the harnessed environments beat both the original environments and domain-specific environment generation pipelines, with up to a 9.0-point gain on held-out instances and 9.8% fewer execution steps. The authors also report that harnessed environments give a better reinforcement learning signal, allowing policy and environment to improve together.

## Direct parents (in Leo's library)
- [J8DYBKW2] ADaPT: As-Needed Decomposition and Planning (Prasad 2023) — established that an agent should decompose a task only when the current subtask fails, making task structure a function of observed agent failure.
- [77ERE7HA] LATS: Language Agent Tree Search (Zhou 2024) — established search over agent trajectories with environment feedback as the value signal, treating the environment as a fixed evaluator.
- [ZULLM3UF] Offline Reinforcement Learning Tutorial (Levine 2020) — set out why a fixed data or task distribution limits what a policy can learn, and why distribution coverage governs final performance.

## Delta from parents
Where ADaPT diagnosed agent failure and changed the *task decomposition* in response, EnvHarness diagnoses agent failure and changes the *environment* in response, because the authors argue the binding constraint is not how the task is split but what situations the environment can present at all. Where LATS treated the environment as a fixed oracle to search against, EnvHarness makes the environment a mutable object while keeping its verifier intact, which is what allows the reshaped environment to remain trustworthy as a reward source. Where the offline RL tutorial framed limited distribution coverage as a property of the collected dataset, EnvHarness treats coverage as something a second system can actively manufacture by rewriting the world the agent acts in. The novel piece is the constraint that reshaping must go through standard interfaces and must not touch the verifier, which is what lets one harness mechanism apply across four unrelated domains.

## Why Leo should care
This sits on the ADaPT-to-LATS bridge already present in the graph, both in Community 0, and pushes it toward Community 7 by making environment construction a reinforcement learning target rather than an engineering cost. For a time-series or bio-sensing group the transferable idea is the separation between a mutable environment wrapper and an immutable verifier: in physiological modelling the analogue is a learned corruption or simulation policy that targets a diagnosed failure regime, such as motion artifact in photoplethysmography, while the clinical label stays untouched. Nothing in Community 4 or Community 5 does this yet, so the transfer is open.
