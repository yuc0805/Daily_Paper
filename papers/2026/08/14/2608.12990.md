# LycheeMemory V2: Efficient Long-Term Memory for LLM Agents via Semantic Segment-Level Consolidation

**Arxiv:** 2608.12990 | **Date:** 2026-08-14 | **Area:** agent

## What it does
Most agent memory systems consolidate eagerly: after every interaction turn they call an LLM to extract, summarize, or update stored memories, so construction cost grows with conversation length. LycheeMemory V2 batches several exchanges into a semantically bounded segment and encodes each finalized segment into context-independent typed memory records, then indexes those records for query-planned retrieval. Semantic boundary detection is what separates this from fixed-window batching; it keeps event-level and temporal evidence coherent. With GPT-4.1-Mini the system reports 89.22 percent on LoCoMo and 92.20 percent on LongMemEval-S, and against A-Mem it cuts construction tokens by 86.0 percent on LoCoMo and 75.9 percent on LongMemEval-S without raising query-time token usage.

## Delta from parents
Where the Memory Mechanisms Survey catalogued *what* to retain, this paper changes *when* consolidation happens and reports that granularity, not retention policy, is the variable that moves the accuracy-cost curve. Where LATS spent extra LLM calls at query time to search over context, LycheeMemory pushes the cost to write time but amortizes it over a segment, so query-time token usage stays flat while construction cost drops by three quarters or more. The framing claim is the useful part: eager per-turn consolidation and coarse summarization are two ends of one axis, and the middle of that axis has not been explored.

## Why Leo should care
The accuracy-cost tradeoff here is stated in tokens, which makes it easy to check against any pipeline that summarizes a long stream. All numbers come from a single backbone, GPT-4.1-Mini, on two conversational benchmarks, so generalization to other model sizes is untested. The transfer worth noting is that continuous wearable sensing has the same structural problem, a long stream that must be compressed into reusable records, and current practice there is fixed-window summarization, which is exactly the baseline this paper beats.
