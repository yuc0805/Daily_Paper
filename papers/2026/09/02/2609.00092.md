# Safin-1: Safety from Within through Memory-Native State Evolution

**Arxiv:** 2609.00092 | **Date:** 2026-09-02 | **Area:** test-time-training

## What it does
Safety in deployed language models is usually a layer around the model, either a separate classifier or a post-hoc fine-tuning pass, and neither survives a long interaction in which the model accumulates context. Safin-1 is a family of foundation models built on MARCH, an architecture that maintains structured memory states and retrieves from context history through content-conditioned routing rather than through full attention over the whole history. The same routed-state interface carries a persistent Safety State that is adapted at test time without touching the backbone weights, so a specialization can be installed and revised on a shared foundation. The paper reports safety improvements from state-based adaptation alongside evaluations of general capability, long-context understanding, retrieval, and efficiency, and describes itself as an initial architectural exploration rather than a finished result.

## Delta from parents
Where Mamba compresses history into a fixed recurrent state and where the memory survey treats stored context as something to be retrieved and read, this paper makes the state writable for a second purpose: it holds a capability, not only a record. That is the substantive claim, and it is what lets a Safety State be installed at test time without a backbone update, because the interface that routes context is the same interface that routes the persistent state. Where TTT Layers adapt an inner state to the current input and discard it, MARCH keeps the adapted state across interactions, which changes the unit of adaptation from a sequence to a deployment. The safety framing follows from the architecture rather than motivating it: if a capability lives in a routed state, then a safety capability can be one of those states and is invoked by the model's own computation instead of by an external check.

## Why Leo should care
Two things here are separable from the safety claim. First, a persistent test-time-adapted state that is not the backbone is the right shape for per-subject adaptation in wearable modelling, where the population model must be shared but each wearer's calibration must persist and be revisable without retraining. The library holds TTT-Unet and TTT Layers, both of which reset per input; none of them keeps the adapted state. Second, treating a capability as a routed state rather than as weights gives a place to put a subject-specific correction that can be audited and removed, which matters in a clinical setting more than it does in a chat setting. The safety evaluations themselves are early and the authors say so.
