# Aspire: Can Models Self-Evolve from Vague Goals?

**Arxiv:** 2608.31111 | **Date:** 2026-09-04 | **Area:** agent

## What it does
ASPIRE is a benchmark in which an agent receives only a natural-language capability goal such as "improve at research" and no downstream task or metric. The agent must interpret the goal, choose training data and update method, build its own training and validation signal, and decide when to stop, with evaluation held out on 520 expert-authored items across six goals. Both weight-level and harness-level self-evolution run in one interactive environment. The result is that agents complete the loops but weight-level gains are sparse and unstable, the best evolved harness stays below the engineered Qwen-Agent reference, agents often train on mismatched data, and continued search can erase earlier gains.

## Delta from parents
Where the memory survey and the Agent AI survey both assume the objective is given and ask how the agent should be built, ASPIRE removes the objective and asks whether the agent can construct one, because specifying the metric is the part of research work that humans currently do and that self-evolution claims implicitly cover. Where Repo-To-Skill improved a fixed agent by mining skills from an external corpus and verifying them against known tasks, ASPIRE denies the agent both the external corpus and the verification target, and the reported failure is precisely at that seam: agents trust narrow self-evaluations, so local gains do not transfer to the hidden set. Read together, the two papers from consecutive days bracket the same question, one showing what external verified knowledge buys and the other showing what its absence costs.

## Why Leo should care
The failure mode named here — an agent that optimises a self-chosen proxy and reports improvement that does not transfer — is the same failure mode that makes automated research pipelines untrustworthy, and it is now measured rather than asserted. The benchmark design is also worth borrowing: hiding the evaluation set is a cheap way to test whether any self-improving system has learned the goal or the proxy, and that design carries directly to a self-tuning sensing pipeline that picks its own validation split.
