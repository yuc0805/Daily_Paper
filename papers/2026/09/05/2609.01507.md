# LatentPress: Context Compression Beyond Text and Vision

**Arxiv:** 2609.01507 | **Date:** 2026-09-05 | **Area:** llm

## What it does
LatentPress writes conversational histories and long documents into continuous memory tokens that a frozen decoder reads directly through its input-embedding interface, with no text reconstruction at inference. A small reader-matched writer compresses 4x to 16x while training only an adapter of 4.2M to 26.2M parameters, roughly 0.1 percent of the decoder. On LongMemEval it reaches 0.504 accuracy at 7.70x compression against 0.490 for uncompressed evidence, 0.184 for text summaries and 0.426 down to 0.312 for OCR-based compression. Writing takes 43 ms per conversation and reading is 5x to 9x faster than raw context or cached OCR.

## Direct parents (in Leo's library)
- [MKICLA63] Time-LLM (2024) — established that a frozen LLM will read a non-text modality if a small trainable adapter reprograms it into the input-embedding space.
- [VSCNJG5J] ChatTS (2025) — graphify `xie2025_chatts`, Community 4 (Time Series + LLM Integration). Trains a bridge that aligns numeric series with language so the LLM can answer questions about the series.
- [743XA29Y] DeepSeek-V2 (2024) — llm area. Multi-head latent attention compresses the KV cache into a low-rank latent, the competing way to reduce the memory cost of long context.

## Delta from parents
Where Time-LLM showed that the input-embedding port of a frozen decoder will accept vectors produced by a small reprogramming adapter, LatentPress shows the same port can carry compressed text at 4x to 16x and beat the obvious text baseline by a wide margin, because the thing it removes is the decode step rather than a modality gap. ChatTS and Time-LLM never reported compression ratio or read and write latency, so the capacity and cost of that interface were unmeasured; this paper measures both in a setting where a strong same-modality baseline exists, which is what makes the number interpretable. Against DeepSeek-V2 the difference is where the compression happens: multi-head latent attention shrinks the per-token state inside attention and keeps the token count, while LatentPress shrinks the token count itself at the input and leaves the decoder untouched. The two are composable rather than competing.

## Why Leo should care
The claim that transfers is about the interface, not the task. This paper puts a number on how much a frozen decoder's embedding port can carry and how cheaply a writer for a new source can be trained, and it does so against a text baseline that scores 0.184 where the compressed representation scores 0.504. Every Community 4 method in Leo's library converts one window of signal into something the LLM reads; none writes a long continuous record into a fixed budget of memory tokens. No graphify cross_area_bridge from `_meta/area_index.json` covers this pair, so it is a candidate new bridge between Community 4 and the LLM context-efficiency line. The imported method is soft-token context compression, and it is not yet closed off for time series or bio-sensing.
