# STELLA: Efficient Sensor-to-LLM Translation for On-Device Human Activity Recognition

**Arxiv:** 2607.03089 | **Date:** 2026-07-15 | **Area:** time-series

## What it does
STELLA treats language-model-based human activity recognition as a tokenization problem rather than a prompting or model-compression problem. A light hierarchical tokenizer turns raw wearable sensor streams into compact, activity-aware tokens, which are then read by a frozen large language model. A local personalization step adapts the system to a single user on the device. The stated goal is accurate recognition that stays private and cheap enough to run in real time on a phone or watch.

## Delta from parents
Where Sensor2Text produced language from sensors using heavy trainable backbones, STELLA freezes the language model and moves the work into a small hierarchical tokenizer that emits activity-aware tokens, so the system fits on an edge device. Where SSL for HAR pretrained an encoder for later fine-tuning, STELLA does not fine-tune the language model at all and instead learns only the tokenizer plus a per-user personalization layer, because that keeps compute, memory, and private data on the device. This paper extends Sensor2Text, which already bridged bio-sensing and llm-health in your library (the chen2024_sensor2text to liu2023_health_llm edge). The new work pushes that bridge toward on-device efficiency: the same sensor-to-language idea, now with a cost budget that a watch can meet.

## Why Leo should care
This is squarely in the primary working area (time-series and bio-sensing). It imports the frozen-LLM-plus-lightweight-adapter recipe from NLP and vision into wearable HAR. That specific move, using a hierarchical learned tokenizer to feed a frozen language model, is now demonstrated for sensors, so it is closing off as low-hanging fruit. The open room is on-device continual personalization and streaming (multi-day) input, which STELLA touches but does not fully solve.
