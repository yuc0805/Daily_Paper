# AgentDebugX: An Open-Source Toolkit for Failure Observability, Attribution, and Recovery in LLM Agents

**Arxiv:** 2607.18754 | **Date:** 2026-07-22 | **Area:** agent

## What it does
LLM agent failures are hard to debug because the step where an error appears is often not the step that caused it. AgentDebugX organizes debugging as a closed loop of Detect, Attribute, Recover, and Rerun. Its core component, DeepDebug, does multi-turn root-cause diagnosis through whole-trajectory understanding, structure-guided investigation, and cross-examination. On the Who and When benchmark it reaches 28.8 percent exact agent-and-step attribution on qwen3.5-9b, against 21.7 percent for the strongest single-pass baseline. On GAIA it repairs 13 of 73 failed tasks in one rerun, against 4 to 6 for decoupled self-correction baselines, lifting accuracy from 55.8 to 63.6 percent. It ships as a Python library, CLI, web console, and an installable agent skill, with an opt-in hub for sharing scrubbed failure-diagnosis-repair bundles.

## Delta from parents
Where the Agent AI Survey described what agents can do and the Memory Mechanisms Survey described how agents store state, this paper addresses what to do when an agent fails and gives measured attribution and repair numbers. Where existing observability tools replay a trace and stop, AgentDebugX closes the loop by turning a diagnosis into a rerun and by storing the repair as reusable memory, which connects the memory-survey idea to concrete failure recovery. It does not add a new agent architecture; it adds a diagnostic layer around the ones the parents describe.

## Why Leo should care
Agents are a tracked area rather than a primary one, but the attribution idea is transferable: separating the step where an error shows from the step that caused it is a general credit-assignment problem, close in spirit to reward attribution in reinforcement learning. If Leo runs agent pipelines over health or sensor data, the Detect-Attribute-Recover-Rerun loop is a practical tool.
