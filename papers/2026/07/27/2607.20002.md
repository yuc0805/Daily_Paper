# Post-Training in Time Series Foundation Models: A Unifying Framework

**Arxiv:** 2607.20002 | **Date:** 2026-07-27 | **Area:** time-series

## What it does
Time series foundation models are pretrained on broad collections of series and then reused across tasks, but pretraining by itself does not give reliable behavior on a specific downstream dataset. This paper organizes the methods that sit between a pretrained model and its deployment into one framework. It sorts post-training methods by where they act in the prediction pipeline and names five families: parameter adaptation, context augmentation, model composition, output processing with uncertainty control, and compression with specialization. For each family it reviews representative methods, states their current limits, and lists open directions.

## Direct parents (in Leo's library)
- [72DFULQQ] Chronos — a pretrained time series foundation model of the kind this framework post-trains; it is the "before" state the survey starts from.
- [I2CIT4I7] TS-Agent — an example of context augmentation, where an LLM controller adds statistical evidence around a series rather than changing model weights.
- [MKICLA63] Time-LLM — an example of model composition and cross-modal alignment, reprogramming a language model backbone for forecasting.

## Delta from parents
Where Chronos supplied a single pretrained model and each later paper (TS-Agent, Time-LLM) proposed one specific way to adapt it, this paper does not add a new method. Instead it places these methods on a shared map keyed by locus of intervention, so a reader can see that TS-Agent and Time-LLM are answering different questions (what evidence surrounds the input versus how the backbone is reused) rather than competing on the same axis. The value is a comparison frame: given a domain shift or a compute limit, which of the five families addresses it, and what does each family still fail to do. This is the missing organizing layer above the individual method papers already in the library.

## Why Leo should care
This is directly in Leo's primary area. It is a map of the exact design space Leo works in, and it separates methods imported from NLP (parameter-efficient tuning, retrieval-style context, calibration) from open gaps. The framework marks parameter adaptation and context augmentation as areas where NLP methods have already been ported into time series, so those are lower-value targets. Uncertainty-aware model composition and deployment-aware specialization are named as thinner areas, which is where new work is more likely to matter.
