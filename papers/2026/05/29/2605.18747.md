# Code as Agent Harness

**Arxiv:** 2605.18747 | **Date:** 2026-05-29 | **Area:** agent

## What it does
This position-and-survey paper reframes code as the substrate that connects an agent to reasoning, action, environment modeling, and execution-based verification, rather than as an output to be generated. It organizes the design space into three layers: the harness interface (how code links the agent to its world), harness mechanisms (planning, memory, tool use, and feedback-driven control for long-horizon execution), and scaling.

## Delta from parents
A graphify cross-area bridge links ToolkenGPT and PyVision as "tool-using agents." This survey extends that bridge. Where ToolkenGPT made tools callable as tokens and PyVision generated and executed code per task, this paper treats code itself as the general harness that unifies tool use, memory, and verification, moving from "agents that call tools" toward "code as the operating layer the whole agent runs on."

## Why Leo should care
If code becomes the standard harness for agents, then a time-series or bio-sensing agent built on executable, verifiable operators fits the pattern directly, and execution-based verification is a clean way to keep numeric claims grounded.
